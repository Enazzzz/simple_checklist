# Contributing to CSV Checklist Application

Thank you for your interest in contributing to the CSV Checklist Application! This document provides guidelines for contributing to the project.

## 🚀 Getting Started

### Prerequisites
- Python 3.6+
- Git
- Basic knowledge of Pygame and Python

### Setting Up Development Environment
1. Fork the repository
2. Clone your fork locally
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Run the application:
   ```bash
   python checklist.py
   ```

## 🐛 Reporting Bugs

Before creating bug reports, please check the existing issues to avoid duplicates. When creating a bug report, include:

- **Clear description** of the problem
- **Steps to reproduce** the issue
- **Expected behavior** vs actual behavior
- **Environment details** (OS, Python version)
- **Screenshots** if applicable

## 💡 Suggesting Features

We welcome feature suggestions! When proposing new features:

- **Describe the problem** the feature would solve
- **Explain your proposed solution**
- **Consider alternatives** you've thought about
- **Provide mockups** or examples if possible

## 🔧 Making Changes

### Code Style
- Follow PEP 8 guidelines
- Use meaningful variable and function names
- Add comments for complex logic
- Keep functions focused and concise

### Testing
- Test your changes thoroughly
- Ensure the application runs without errors
- Test with different CSV files
- Verify UI elements work correctly

### Commit Messages
Use clear, descriptive commit messages:
```
feat: add keyboard shortcuts for navigation
fix: resolve checkbox click detection issue
docs: update README with new features
style: improve code formatting
```

## 📝 Pull Request Process

1. **Create a feature branch** from `main`
2. **Make your changes** following the guidelines above
3. **Test thoroughly** before submitting
4. **Update documentation** if needed
5. **Submit a pull request** with a clear description

### Pull Request Guidelines
- **Clear title** describing the change
- **Detailed description** of what was changed and why
- **Screenshots** for UI changes
- **Reference related issues** if applicable

## 🎨 UI/UX Contributions

When contributing to the user interface:

- **Maintain the dark theme** consistency
- **Follow existing patterns** for colors and spacing
- **Test on different screen sizes** if applicable
- **Ensure accessibility** considerations

## 📋 Development Workflow

1. **Fork** the repository
2. **Create** a feature branch
3. **Make** your changes
4. **Test** thoroughly
5. **Commit** with clear messages
6. **Push** to your fork
7. **Submit** a pull request

## 🤝 Code Review

All contributions go through a review process:

- **Automated checks** must pass
- **Code review** by maintainers
- **Testing** on different environments
- **Documentation** updates if needed
